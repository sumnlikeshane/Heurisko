## Real blockers versus unfinished local work

Native Linux amd64 parser/recovery/resource proof requires that host and its local Docker boundary; emulation of the hosted image does not supply it. Sandbox-denied Docker/listeners, missing cached dependencies/DNS, and blocked/intermittent browser tooling are recorded access/environment failures, not passes. Human visual/AT review, owner acceptance, rights evidence unavailable locally and authoritative deployed identity can also require external access or a human decision.

Explicit approval is still required for concrete commits, pushes, PR publication, merge, deploy/release/submission or external messages, and material trust/compatibility/scope changes. The current task authorizes none of those. Exact new-head remote CI therefore remains pending publication; it is not a reason to leave independent local work unfinished.

Reading full docs, extracting findings, fixing current references/anchors, reconciling historical links, maintaining the existing plan, reviewing source/CI/scripts, defining acceptance and running relevant available local checks did not require another approval. Remaining Phase 1 rights/configuration/corpus/compatibility/measurement work also has independent local portions, but completing that phase is outside this task. Its plan now names each blocker, evidence, resolution condition and independent work.

## Canonical structure and retirement rule

[The docs index](../README.md) maps subjects to their authority. Contributors follow [AGENTS](../../AGENTS.md#one-development-workflow); they do not need event handoffs. Current blockers live in the Phase 1 matrix, durable decisions in the register, future issues in the roadmap. Component guides own actual behavior; source/schema/validators remain the executable truth.

Update the owning reference and item status alongside implementation. Retire superseded prose in the same change after extracting active technical decisions, unresolved findings and operating commands. Use exact Git history for redundant plans. Retain an archive only for a stated legal/attribution/approval/reproduction need; do not keep obsolete instructions just because they are linked. Reconcile all mutable references, protect pinned originals, validate links/routes/hashes and review the resulting contributor path.
